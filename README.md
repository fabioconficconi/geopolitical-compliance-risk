# Geopolitical Compliance Risk

Applied Statistics project (Politecnico di Milano) developed with **PwC Italy**.
Goal: a compliance risk score for Italian firms, based on how much their sector trades
with sanctioned or high-risk countries.

- **Layer 1 — Country risk.** PCA + hierarchical (Ward) clustering on institutional
  quality (WGI), logistics (LPI), sovereign credit risk (OECD CRC), sanctions
  (OpenSanctions) and involvement in sanctions-evasion routing. Output: a continuous
  risk score in [0, 1] and a cluster label for each country.
- **Layer 2 — Firm compliance risk.** For each sector (CPA) it measures exposure to
  high-risk countries (imports, exports, circumvention), combines the three components
  into a `compliance_score`, assigns it to firms, computes a **financial-fragility
  score** (PCA on balance-sheet ratios) and crosses the two into four **risk quadrants**.
  A companion script validates the clusters (MANOVA) and tests the robustness of the
  weights (sensitivity analysis).

> [`docs/METHODOLOGY.md`](docs/METHODOLOGY.md) walks through the economic data, the
> transformations, PCA, clustering, weights and limitations step by step.

## How to run the pipeline (mandatory order)

The four steps run **in sequence**: each step reads the output of the previous one.
Run every command **from the repository root**.

**Step 1 — Python**
```bash
python scripts/01_build_layer1.py
```
Reads the raw data from `data/raw/` and writes `data/processed/layer1_input.csv`.

**Step 2 — R**
```bash
Rscript scripts/02_layer1_analysis.r
```
Or open the file in RStudio and *Source* it. Reads `layer1_input.csv`, runs PCA +
clustering, and writes `data/processed/layer1_countries.csv`.

**Steps 3 + 4 — R, in the SAME session**

`04_Layer2_analysis.r` reuses objects that `03_Layer2.r` leaves **in memory**
(`firms`, `all_components`, `l1`, `COMP_THRESH`, `FRAG_THRESH`). They must therefore
run in one R session, with step 4 right after step 3.

- **RStudio (recommended, since the scripts display charts):** open `03_Layer2.r` and
  *Source* it; then, **without restarting the session**, open `04_Layer2_analysis.r`
  and *Source* it.
- **Terminal (one session):**
  ```bash
  Rscript -e 'source("scripts/03_Layer2.r"); source("scripts/04_Layer2_analysis.r")'
  ```

Step 3 writes `layer2_firms_v2.csv`, `layer2_sector_components_v2.csv` and
`layer2_trade_detail.csv` to `data/processed/`. Step 4 produces only charts and console
output (the MANOVA result and the sensitivity statistics).

> **Charts.** Both R scripts *display* their charts (via `print()`); they are not saved
> to disk by default. In RStudio they appear in the Plots pane. To save one, wrap it in
> `ggsave("name.png", plot, width = …, height = …)`.

## Input → output map

| Step | Script | Main inputs | Outputs |
|------|--------|-------------|---------|
| 1 | `01_build_layer1.py` | `iso3_reference`, `wgi`, `lpi`, `oecd_crc`, `opensanctions_by_country`, `circumvention_hubs` | `layer1_input.csv` |
| 2 | `02_layer1_analysis.r` | `layer1_input.csv`, `iso3_reference` | `layer1_countries.csv` |
| 3 | `03_Layer2.r` | `layer1_countries.csv`, `istat_trade`, `db_polimi_final`, `eurostat_ext_tec03` | `layer2_firms_v2.csv`, `layer2_sector_components_v2.csv`, `layer2_trade_detail.csv` + 6 charts |
| 4 | `04_Layer2_analysis.r` | in-memory objects from step 3 + `layer1_input.csv`, `layer1_countries.csv` | MANOVA result + sensitivity stats + 3 charts |

Notes:
- **Firm-level data is not included.** `db_polimi_final.csv` (firm financials) comes from
  AIDA (Bureau van Dijk), a licensed database, and cannot be redistributed. Layer 1 runs
  on the public data; Layer 2 needs a firm file with the same columns (see
  `data/README.md`).
- `data/processed/` ships with **pre-computed country- and sector-level outputs** so the results      can be inspected without re-running everything. Re-running step 3 creates the `…_v2.csv` files
  alongside them.
- `layer1_pca_loadings.csv` in `data/processed/` is a supporting export, not
  regenerated automatically by the scripts.
- Auxiliary files in `data/raw/` (`eu_crm_list.csv`, `eurostat_trade_sitc_paese.csv`)
  are kept for possible extensions; they are not scored inputs of the current pipeline.
  AIDA extractions (`aida_all_batches.csv`, `db_polimi.xlsx`) are not included for
  licensing reasons.
